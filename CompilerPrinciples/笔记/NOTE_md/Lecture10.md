# 活动记录（或帧） (Page 8/34)

- **活动记录的典型组织**
  - 实际参数：被调用者设置，寄存器优先
  - 返回值：调用者设置，寄存器优先
  - 控制链：指向调用者的AR的指针
  - 访问链：指向外层AR的指针
  - 保存的机器状态：返回地址和寄存器
  - 局部数据：用户定义
  - 临时变量：编译器生成

# 活动记录设计 (Page 12/34)

- **设计原则**
  - 调用者不知道被调用者的局部数据和临时变量！
  - 1.靠近调用者的AR，便于调用者设置实际参数和获取返回值
  - 2.固定项放在中间，调试器也可以访问
  - 3.可变长度项放在末尾，例如动态数组

<img src="./images/10_5.png" width="50%">

# 调用序列 (Page 13/34)

- **典型的调用序列**
  1. 调用者计算实际参数
  2. 调用者将返回地址和旧的top_sp存储到被调用者的活动记录中
  3. 调用者将活动记录压入栈（增加top_sp）
  4. 被调用者保存寄存器值和其他状态信息
  5. 被调用者初始化局部数据并开始执行

# 返回序列 (Page 14/34)

- **典型的返回序列**
  1. 被调用者设置返回值
  2. 被调用者弹出活动记录（减少top_sp）
  3. 被调用者恢复寄存器
  4. 被调用者跳转到状态字段中的返回地址
  5. 调用者获取返回值（即使top_sp已减少）

# 标记-清除（续） (Page 24/34)

- **优点**
  - 如果垃圾很少，效率很高
  - 能够收集循环引用
- **缺点**
  - 垃圾量大时效率低
    - H. Baker（1992）的改进
    - 保持所有分配对象的列表
  - 修改器（程序）的暂停使其难以应用于实时应用
  - 导致堆中的碎片化

# 标记-压缩（续） (Page 26/34)

- **3个步骤**
  1. 标记阶段：类似于标记-清除
  2. 为每个可达对象从堆的低端计算新地址
  3. 将对象复制到新位置并更新根区域和对象中的所有引用
- **优缺点**
  - 优点：改善空间使用和程序局部性，避免碎片化
  - 缺点：第3步（压缩中的复制）很昂贵
    - 更新引用简单快速

# 复制收集器（续） (Page 28/34)

- **堆被划分为2个半空间**
  - 可达对象一旦被发现就立即移动
  - 不触及任何不可达对象
- **优点**
  - 更高效和流行
- **缺点**
  - 只能利用一半的堆内存

# JVM中的实现 (Page 31/34)

- **使用两代（年轻代和老年代）方法**
- **年轻代：复制收集器**

- **老年代：标记-压缩**
